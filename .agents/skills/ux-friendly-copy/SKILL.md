---
name: ux-friendly-copy
description: Use when writing UI text, validation errors, empty states, booking explanations, price explanations, onboarding help, complaint forms, and notifications.
---

Tone:
- calm
- clear
- friendly
- non-technical
- short on mobile
- never blaming the user

Every message must be translatable.

Use:
- "Почти готово"
- "Остался один шаг"
- "Проверьте детали перед бронированием"
- "Мы покажем итоговую цену заранее"
- "Это место может не подойти по вашим предпочтениям"
- "Можно изменить позже"
- "Сохранено"
- "Готово"

Avoid:
- "Error"
- "Invalid"
- "Failed"
- "Forbidden"
- "Bad request"
- raw exception messages
- technical database words

For errors:
1. Say what happened.
2. Say why, if useful.
3. Say what to do next.

For booking:
- Always explain nights.
- Always explain deposit.
- Always explain refundable vs non-refundable.
- Always explain cancellation.
- Always show rules before payment.
